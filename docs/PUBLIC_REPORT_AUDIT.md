核验日期：2026-11-10。

## 来源与证据边界

本轮检索公开 CSV/XLSX、报告模板、精确字段及附件。找到了官方字段说明和不同年份的公开截图，未取得完整、可直接导入的真实卖家原始文件。截图不能证明文件编码、完整行结构或总计准确性；转载不视为独立卖家样本。

| 来源 | 实际可核验内容 | 限制 |
| --- | --- | --- |
| [Amazon SP-API 官方文档](https://developer-docs.amazon/sp-api/docs/report-type-values-regulatory-compliance) | 月度、季度、年度 EPR 报告字段清单，34 个公开字段 | 字段规范，不是实际卖家文件 |

下载的公开截图及 URL、SHA-256 清单保存在本机 Downloads/EPR公开样本核验_20261110，不作为客户数据或完整报告入库。

## 可复现实测

运行 `node scripts/audit-public-epr-schema.mjs`，按公开 34 字段构造三份**合成诊断文件**：大写季度初级包装、大写年度次级包装、小写月度初级包装。数值由测试设定，不从截图猜测或声称为真实报表。结果写入 `output/public-schema-audit/result.json`。

## v0.1.3 适配后结果

上述三种合成结构再次实际运行，每份 1 行原报告展开为 7 个材料明细，确认测试口径后均为 7 条纳入、0 条待处理；每组数量保持 100，不因七种材料变成 700。原始材料列保持不变。

| 原缺口 | 当前处理 |
| --- | --- |
| 账号与归属 | 报告账户／商城作为明确标注的分组范围，可填写实际客户店铺名称，不推断身份 |
| 期间起止 | 合并并校验日期，支持斜杠和连字符格式；按所选月／季／年筛选 |
| 销量 | 读取 total_units_sold，不额外乘 units_per_asin |
| EEE | 使用 total_reported_weight_kg，保留原报告子分类 |
| 两类包装 | 分别转换为初级和运输包装，分组保持独立 |
| 七种材料列 | 已填项展开为明细，按本行总 kg；零值保留，空白未知且不补零 |
| 数量重复 | 原始行 ID 用于消除材料拆分的重复，业务和层级分别核对；重复原始行仍需确认 |
| 追溯导出 | 原始数据保持原行数；标准化明细记录材料来源列、版本与原始行 ID |

另用一份用户指定的实际报告完成本地浏览器导入、分类汇总、Excel 下载及读回核对，原始行 7、计算明细 26。实际文件和数值未作为公开合成样本入库。见 VALIDATION.md。

网络恢复后，已重新读取 Amazon SP-API 官方月度／季度／年度字段清单。Seller Central 字段说明的公开检索摘要再次确认 TOTAL_REPORTED_WEIGHT_KG 是报告期间售出单位的总 kg，PAPER_KG 是报告销售对应的包装纸重量；该帮助页正文仍受登录展示限制。转换仍要求人工确认本行总 kg 和数据归属，不添加机构规则。文件结构适配不等于法定责任、退货口径、估算可接受性或正式模板核验。未知类别、缺失重量、无效期间与来源冲突仍待处理。
